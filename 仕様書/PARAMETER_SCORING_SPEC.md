# 青春モンスター図鑑 FUKUOKA
## パラメータ算出 技術仕様書

---

## 用語リファレンス

| 用語 | 定義 |
|---|---|
| **パラメータ** | 各モンスターが持つ6つの数値指標。青春力・癒やし力・行動力・知性力・ワクワク力・寄り道力 |
| **baseScore** | オープンデータから算出した生の基礎値。補正前の数値 |
| **reliability（信頼係数）** | データの粒度（精度）に応じた補正係数。粒度が粗いほど小さい値をかけてスコアを抑制する |
| **characterBonus** | 街・施設のキャラクター性を表現するための加算補正。オープンデータだけでは表現できない文化的特徴に対して付与する |
| **cultureBonus** | 歴史・文化・地域の象徴性に基づく加算補正。主にSSRエントリー（神社仏閣）に適用する |
| **minimumScore** | 下限保証値。データが薄いエントリーでも最低限この値を確保する |
| **finalScore** | 算出式の最終出力値。モンスターのJSONに格納される実際の値 |
| **dominant** | 6パラメータのうち最も高い値を持つパラメータ。そのモンスターの「個性」を一言で表す |
| **SSR** | Super Special Rare。神社仏閣6件に付与される特別区分。通常の6パラメータに加え「ラッキーポイント」テキストを持つ |
| **オープンデータ** | 福岡市が公開するBODIKデータ。人口・飲食店・公園・地下鉄乗降者数・学校・図書館等のCSV |
| **キャラ補正** | characterBonus と cultureBonus の総称。根拠コメントの記載を必須とする |

## パラメータ定義

| パラメータID | 表示名 | 元データの解釈 | 主なデータソース |
|---|---|---|---|
| `seishun` | 青春力 | 若者人口・転入数 | fukuokajinkou_202604.csv |
| `iyashi` | 癒やし力 | 公園・自然・スポーツ施設 | tosikouen2018.xlsx / soprts202501.csv |
| `kodo` | 行動力 | 地下鉄乗降者数 | tikattetujyoushasu.xlsx |
| `chisei` | 知性力 | 図書館・学校数 | tosyokan202501.csv / fukuokasyoutyugakkou_201905.csv |
| `wakuwaku` | ワクワク力 | 飲食店数・屋台数 | fukuokainsyoku_202604.csv / 20260522_yatai_opendata_r2.csv |
| `yorimichi` | 寄り道力 | カフェ・公園の複合密度 | fukuokainsyoku_202604.csv / tosikouen2018.xlsx |

## 算出式

```
finalScore = clamp(
  max(
    round(baseScore × reliability + characterBonus + cultureBonus),
    minimumScore
  ),
  30,
  98
)
```

### 各変数の詳細

**baseScore**

対象エリア・施設の周辺データをカウントし、全エントリー間での相対値に変換したもの。
変換方法はパラメータごとに異なる（件数の対数変換、乗降者数の正規化など）。

**reliability（信頼係数）**

| データ粒度 | 係数 | 適用例 |
|---|---|---|
| 街・丁目単位 | 1.00 | Tier1の街エントリー全般 |
| 駅単位 | 0.95 | 博多駅・地下鉄最寄り施設 |
| 住所キーワードマッチ | 0.92 | 「天神」「博多」等の文字列で絞り込んだ場合 |
| 区単位 | 0.82 | 施設の正確な住所が特定できず区全体で集計した場合 |

係数の数値は統計的根拠ではなく設計判断。「丁目レベルと区レベルを同等に扱うべきでない」という直感から設定した。

**characterBonus / cultureBonus**

オープンデータだけでは表現できない街・施設の実態を加算する補正値。

- 設定に制限はないが、**必ず根拠コメントを残す**
- 補正なしで算出できる場合は 0 とする
- 自治体向けには「文化的特徴を反映するためのエリア補正」として説明する

適用例：

```json
{
  "id": "ropponmatsu",
  "characterBonus": 15,
  "characterBonusReason": "九大移転後の学生街化・カフェ密度増加を知性力に加算"
}
```

**minimumScore**

データが薄いエントリーでも一定水準を確保するための下限保証。
エントリーごとに個別設定する。愛宕神社のように周辺データが極端に少ない場合に機能する。

**clamp(value, 30, 98)**

- 下限 30：全モンスターが「ある程度輝いている」ように見せるためのデザイン判断。データ的根拠なし
- 上限 98：「完璧な街はない」という世界観を数値で表現するためのデザイン判断。100にしない

## データ根拠とキャラ補正の分離原則

このプロジェクトの優先順位は以下の順。

```
1. キャラクターとして面白い
2. 福岡市民が納得する
3. オープンデータで説明できる
```

オープンデータは「根拠」であって「答え」ではない。
データが示す値が世界観・キャラクター性と乖離する場合、キャラ補正で調整してよい。
ただし補正の根拠は必ずコメントとして残し、「なぜその値か」を追跡可能にする。

## dominant の扱い

dominant は算出式の出力ではなく、finalScore の6値を比較して事後的に決まる。

```
dominant = argmax({ seishun, iyashi, kodo, chisei, wakuwaku, yorimichi })
```

同点の場合はパラメータの優先順位（事前定義）で解決する。

### dominant 分布制約

新規エントリー追加時、dominant が既存エントリーと完全に重複しても構わないが、
**レーダーチャートの形（セカンドパラメータの組み合わせ）が他エントリーと明確に異なること**を確認する。

現状の分布（全24件）：

| dominant | 件数 |
|---|---|
| 癒やし力 | 8 |
| 行動力 | 4 |
| ワクワク力 | 4 |
| 青春力 | 3 |
| 知性力 | 3 |
| 寄り道力 | 2 |

癒やし dominant 8件は集中しているが、各エントリーの値・セカンドパラメータがすべて異なるため許容済み。

## SSR エントリーの扱い

神社仏閣6件（櫛田神社・東長寺・筥崎宮・住吉神社・警固神社・愛宕神社）は SSR 区分。

パラメータ算出の式・制約は通常エントリーと同一。
SSR であることによるパラメータ上の特別扱いはない。

差別化は以下で行う。

- JSONに `"ssr": true` フィールドを付与
- 詳細ページに「ラッキーポイント」テキストを別枠で追加表示（おみくじ型ランダム）
- 発見時の演出を通常より豪華にする（実装時に設計）

### SSR 選定基準

1. 福岡市内であること（太宰府天満宮・南蔵院は市外のため除外済み）
2. 福岡市民が「ないと不自然」と感じる認知度があること
3. 愛宕神社のようにデータが極端に薄い場合も、条件2を満たせば特例採用する

---

## 新規エントリー追加時のチェックリスト

1. 福岡市民の認知度が「当然ある」レベルか
2. オープンデータで最低限の baseScore が算出できるか（薄い場合はキャラ補正で補う）
3. dominant・セカンドパラメータが既存エントリーと明確に差別化されているか
4. 名前のサフィックスが同一のエントリーが既に2体以上いないか
5. キャラ補正を使った場合、根拠コメントを記載したか

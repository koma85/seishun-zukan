# 青春モンスター図鑑 FUKUOKA
## 企画仕様書 MVP v1.1

---

## 1. 企画概要

### タイトル（仮）
青春モンスター図鑑 FUKUOKA

### コンセプト
福岡の街やランドマークを「青春生物（青春モンスター）」として解釈・可視化するWebサービス。
ユーザーは「青春研究員」として街の生態を観察し、図鑑を集めながら福岡の魅力を発見する。

### 目的
- 福岡のオープンデータを若者が楽しめる形に変換する
- 街の個性をゲーム感覚で学べるようにする
- 診断結果や図鑑カードのSNS拡散を狙う

---

## 2. やること・やらないこと

### やること
- 街の個性をオープンデータから読み解く
- 図鑑を集める体験
- 自分と街の相性を診断する
- SNS映えする図鑑カードの共有

### やらないこと
- GPS・AR・捕獲ゲーム
- バトル・数値競争型ランキング
- ログイン・マルチプレイ
- データの直接表示

## 4. 青春パラメータ

オープンデータをエンタメ向けに再解釈した6指標。数値レンジは1〜100。

| パラメータ | 元データの解釈 |
|---|---|
| 青春力 | 若者人口 |
| 癒やし力 | 公園・自然 |
| 行動力 | 駅・交通アクセス |
| 知性力 | 図書館・教育施設 |
| ワクワク力 | イベント・文化施設 |
| 寄り道力 | カフェ・立ち寄りスポット |

---

## 5. モンスター構成

各図鑑エントリーのデータ構造。

```
id            : 一意識別子（例: "tenjin-01"）
tier          : 1 または 2
name          : モンスター名（例: "テンジニアン"）
classification: 分類（例: "都市型青春種"）
attribute     : 属性（例: "賑わい属性"）
habitat       : 生息地（街またはランドマーク名）
parameters    : 青春力・癒やし力・行動力・知性力・ワクワク力・寄り道力（各1〜100）
ecology       : 生態説明（80文字以内・1文）
researchNote  : 分類名 + 観察記録3件
compatibility : 相性の良い診断タイプID
illustration  : イラスト画像パス
```

---

## 6. 診断機能

### 方式
5問・4択のスコアリング方式。各選択肢が6パラメータにスコアを加算し、
合計スコアの最大値パラメータで診断タイプを決定する。

### 診断タイプ（6種）

| タイプID | 支配パラメータ | ラベル |
|---|---|---|
| wanderer | 寄り道力 | 寄り道系研究員 |
| scholar | 知性力 | 文献型研究員 |
| explorer | 行動力 | 行動派研究員 |
| healer | 癒やし力 | 癒やし系研究員 |
| enthusiast | ワクワク力 | 熱血型研究員 |
| native | 青春力 | 青春純正種 |

### 診断結果で表示するもの
- 診断タイプ名
- 相性の良い街トップ3
- AIコメント（事前生成・静的テキスト）

## 7. コンテンツ生成方針

すべて開発時に1回生成して静的JSONに保存する。本番環境ではAPIを使用しない。

| コンテンツ | 生成手段 | タイミング |
|---|---|---|
| 生態説明・研究ノート | Claude.ai（手動コピペ） | 開発時に1回 |
| モンスターイラスト | Gemini（無料枠）| 開発時に1回 |
| OGP画像 | @vercel/og（自動生成） | アクセス時 |

---

## 8. 進捗の保持

ログイン不要。localStorageに保存する。

```
discoveredIds   : 閲覧済みモンスターIDの配列
diagnosisResult : 診断タイプID・スコア・実施日時
```

デバイスをまたいだ同期は対象外。UI上にリセット機能を設ける。

---

## 9. OGP仕様

@vercel/og（Edge Function）を使用してサーバーサイドでPNG生成。
AIや外部画像生成サービスは使用しない。

| エンドポイント | 内容 |
|---|---|
| /api/og/monster/[id] | 図鑑カード（モンスター名・パラメータ・生態説明） |
| /api/og/diagnosis | 診断結果カード（タイプ名・相性の街） |
